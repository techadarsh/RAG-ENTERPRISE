## 2. Query Optimization

### 2.1 Query Preprocessing

**Query Normalization**:
```python
import re
from typing import str

def normalize_query(query: str) -> str:
    # Convert to lowercase
    query = query.lower()
    
    # Remove extra whitespace
    query = re.sub(r'\s+', ' ', query).strip()
    
    # Remove special characters (optional, test impact on embeddings)
    # query = re.sub(r'[^\w\s]', '', query)
    
    return query

# Before: "  What is    OUR    PTO policy?!?  "
# After:  "what is our pto policy?!?"
```

**Query Expansion** (add synonyms):
```python
from nltk.corpus import wordnet

def expand_query(query: str) -> str:
    words = query.split()
    expanded = []
    
    for word in words:
        expanded.append(word)
        # Add synonyms
        for syn in wordnet.synsets(word):
            for lemma in syn.lemmas()[:2]:  # Limit to 2 synonyms
                if lemma.name() != word:
                    expanded.append(lemma.name())
    
    return ' '.join(expanded)

# Before: "remote work policy"
# After:  "remote work policy distant employment guideline"
```

**Impact**: Query expansion can improve recall by 10-20% but may increase latency by 15-30ms due to longer embedding time. Test carefully.

```python
@lru_cache(maxsize=1000)

def get_cache_key(query: str, user_id: str) -> str:
```

**Redis Cache** (distributed):
```python
import redis
import json

redis_client = redis.Redis(host='localhost', port=6379, db=0)
CACHE_TTL = 3600  # 1 hour

def query_rag_with_redis_cache(query: str, user_id: str):
    cache_key = f"rag:{get_cache_key(query, user_id)}"
    
    # Check cache
    cached = redis_client.get(cache_key)
    if cached:
        print("Cache HIT")
        return json.loads(cached)
    
    print("Cache MISS")
    # Generate answer
    result = query_rag(query)
    
    # Store in cache
    redis_client.setex(cache_key, CACHE_TTL, json.dumps(result))
    
    return result
```

```python
def embed_with_cache(text: str):

# Persist cache to disk

def load_cache():
    global embedding_cache
    try:
        with open('embedding_cache.pkl', 'rb') as f:

    except FileNotFoundError:
        embedding_cache = {}
```

## 4. Vector Search Optimization

### 4.1 Milvus Index Tuning

**HNSW Index Parameters**:

| Parameter      | Description                | Default | Recommended | Impact on Performance         |
|----------------|----------------------------|---------|-------------|-------------------------------|
| M              | Max connections per node   | 16      | 32          | Higher = better recall, more memory |
| efConstruction | Build-time search depth    | 200     | 256         | Higher = better index, slower build |
| ef             | Search-time depth          | 64      | 128         | Higher = better recall, slower search |

**Create Optimized Index**:
```python
from pymilvus import Collection, FieldSchema, CollectionSchema, DataType

# Define collection schema
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=1024),
    FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=65535),
]
schema = CollectionSchema(fields, description="RAG knowledge base")
collection = Collection(name="documents", schema=schema)

# Create HNSW index with optimized parameters
index_params = {
    "metric_type": "L2",
    "index_type": "HNSW",
    "params": {
        "M": 32,              # Higher for better recall (memory +50%)
        "efConstruction": 256  # Higher for better index quality
    }
}

collection.create_index(field_name="embedding", index_params=index_params)

# Search with optimized parameters
search_params = {
    "metric_type": "L2",
    "params": {
        "ef": 128  # Higher for better recall (latency +20%)
    }
}

results = collection.search(
    data=[query_embedding],
    anns_field="embedding",
    param=search_params,
    limit=5
)
```

**Parameter Tuning Trade-offs**:

```
M: 16 → 32
- Recall: 92% → 97% (+5%)
- Memory: 4 GB → 6 GB (+50%)
- Search latency: 28ms → 32ms (+14%)
Recommendation: Use M=32 for better recall

efConstruction: 200 → 256
- Recall: 95% → 97% (+2%)
- Index build time: 10 min → 14 min (+40%)
- Search latency: No change
Recommendation: Use efConstruction=256 (one-time cost)

ef: 64 → 128
- Recall: 94% → 98% (+4%)
- Search latency: 28ms → 34ms (+21%)
Recommendation: Use ef=128 (acceptable latency increase)
```

### 4.4 Connection Pooling

**Milvus Connection Pool**:
```python
from pymilvus import connections
from queue import Queue
import threading

class MilvusConnectionPool:
    def __init__(self, size: int = 10):
        self.pool = Queue(maxsize=size)
        for i in range(size):
            connections.connect(alias=f"conn_{i}", host="localhost", port="19530")
            self.pool.put(f"conn_{i}")
    
    def get_connection(self):
        return self.pool.get()
    
    def release_connection(self, conn):
        self.pool.put(conn)

# Usage
pool = MilvusConnectionPool(size=10)

def search_with_pool(query_embedding):
    conn = pool.get_connection()
    try:
        collection = Collection("documents", using=conn)
        results = collection.search(...)
        return results
    finally:
        pool.release_connection(conn)

# Performance:
# Without pooling: 28ms search + 5ms connection overhead = 33ms
# With pooling: 28ms search + 0ms overhead = 28ms (15% faster)
```

### 5.2 Context Pruning

**Problem**: Long context (5 documents × 500 tokens = 2,500 tokens) increases latency

**Solution**: Prune context to only relevant parts

**Rank Documents by Score**:
```python
def select_top_documents(results, max_documents: int = 3, min_score: float = 0.7):
    # Filter by score
    filtered = [r for r in results if r.score > min_score]
    
    # Take top N
    top_results = sorted(filtered, key=lambda r: r.score, reverse=True)[:max_documents]
    
    return top_results

# Before: 5 documents, 2,500 tokens, 1,207ms
# After:  3 documents, 1,500 tokens, 856ms (29% faster)
```

**Extract Only Relevant Sentences**:
```python
from sentence_transformers import util

def extract_relevant_sentences(document: str, query_embedding, top_k: int = 3):
    # Split into sentences
    sentences = document.split('. ')
    
    # Embed sentences
    sentence_embeddings = model.encode(sentences)
    
    # Compute similarity
    similarities = util.cos_sim(query_embedding, sentence_embeddings)[0]
    
    # Get top sentences
    top_indices = similarities.argsort(descending=True)[:top_k]
    relevant_sentences = [sentences[i] for i in top_indices]
    
    return '. '.join(relevant_sentences)

# Before: Full document (500 tokens)
# After:  Top 3 sentences (~100 tokens, 80% reduction)
```

### 5.4 Batch Generation (Multiple Queries)

**Process Multiple Queries in Parallel**:
```python
import asyncio
from concurrent.futures import ThreadPoolExecutor

async def generate_batch(queries: List[str], contexts: List[str]):
    with ThreadPoolExecutor(max_workers=4) as executor:
        loop = asyncio.get_event_loop()
        tasks = [
            loop.run_in_executor(executor, generate_answer, ctx, q)
            for q, ctx in zip(queries, contexts)
        ]
        answers = await asyncio.gather(*tasks)
    return answers

# Performance:
```

## 6. Caching Strategies

### 6.1 Multi-Layer Caching

**Layer 1: Application Cache** (fastest, limited size):
```python
from functools import lru_cache

@lru_cache(maxsize=100)  # Last 100 queries
def get_answer_l1(query: str):
    return query_rag(query)
```

**Layer 2: Redis Cache** (fast, larger capacity):
```python
def get_answer_l2(query: str):
    cache_key = f"rag:{hashlib.md5(query.encode()).hexdigest()}"
    cached = redis_client.get(cache_key)
    if cached:
        return json.loads(cached)
    
    answer = query_rag(query)
    redis_client.setex(cache_key, 3600, json.dumps(answer))
    return answer
```

**Layer 3: Database Cache** (persistent):
```python
def get_answer_l3(query: str):
    # Check PostgreSQL cache table
    result = db.execute("SELECT answer FROM query_cache WHERE query_hash = %s", [hash(query)])
    if result:
        return result[0]['answer']
    
    answer = query_rag(query)
    db.execute("INSERT INTO query_cache (query_hash, query, answer, created_at) VALUES (%s, %s, %s, NOW())", 
               [hash(query), query, answer])
    return answer
```

**Combined Multi-Layer Cache**:
```python
def get_answer_cached(query: str):
    # Try L1 (in-memory)
    answer = get_answer_l1(query)
    if answer:
        return answer
    
    # Try L2 (Redis)
    answer = get_answer_l2(query)
    if answer:
        # Populate L1
        get_answer_l1.cache_info()  # Warm L1 cache
        return answer
    
    # Try L3 (database)
    answer = get_answer_l3(query)
    if answer:
        # Populate L2 and L1
        redis_client.setex(cache_key, 3600, json.dumps(answer))
        return answer
    
    # Cache miss - generate answer
    answer = query_rag(query)
    
    # Populate all layers
    get_answer_l1(query)  # L1
    redis_client.setex(cache_key, 3600, json.dumps(answer))  # L2
    db.execute("INSERT INTO query_cache ...")  # L3
    
    return answer

# Performance:
# L1 hit: <1ms
# L2 hit: 3-5ms
# L3 hit: 15-20ms
# Cache miss: 1,287ms
```

### 6.2 Cache Warming

**Pre-populate Cache with Common Queries**:
```python
COMMON_QUERIES = [
    "What is our PTO policy?",
    "How do I request time off?",
    "What is our remote work policy?",
    "How do I access VPN?",
    "What are our company holidays?"
]

def warm_cache():
    for query in COMMON_QUERIES:
        answer = query_rag(query)

    print(f"Warmed cache with {len(COMMON_QUERIES)} queries")

# Run on startup
warm_cache()
```

**Periodic Cache Refresh** (keep cache fresh):
```python
import schedule

def refresh_cache():
    print("Refreshing cache...")
    for query in COMMON_QUERIES:
        answer = query_rag(query)
        redis_client.setex(cache_key, 86400, json.dumps(answer))
    print("Cache refreshed")

# Run every 6 hours
schedule.every(6).hours.do(refresh_cache)
```

### 6.3 Cache Invalidation

**Invalidate on Document Update**:
```python
def on_document_updated(document_id: str):
    # Option 1: Clear entire cache (simple but wasteful)
    redis_client.flushdb()
    
    # Option 2: Track query-document relationships
    affected_queries = get_queries_using_document(document_id)
    for query in affected_queries:
        cache_key = f"rag:{hashlib.md5(query.encode()).hexdigest()}"
        redis_client.delete(cache_key)
```

**Time-based Expiration** (TTL):
```python
# Short TTL for frequently changing data
redis_client.setex(cache_key, 1800, answer)  # 30 minutes

# Long TTL for stable data
redis_client.setex(cache_key, 86400, answer)  # 24 hours
```

## 12. Common Bottlenecks & Solutions

### 12.1 LLM Generation Bottleneck (Most Common)

**Symptom**:
- Query latency: 1,200-2,000ms
- 90%+ of time spent in LLM generation

**Solutions**:

1. **Use GPU**: 4-8x speedup (1,207ms → 150-300ms)
2. **Smaller model**: Mistral 7B → Mistral 3B (1,207ms → 600ms, but lower quality)
3. **Aggressive quantization**: Q4_K_M → Q3_K_M (1,207ms → 980ms)
4. **Context pruning**: 5 docs → 3 docs (1,207ms → 856ms)
5. **Streaming**: Improve perceived performance (first token at 50ms)
6. **Caching**: 70% cache hit rate reduces average to 360ms

**Recommended**: GPU + caching (1,207ms → 287ms, 76% reduction)

### 12.2 Embedding Bottleneck

**Symptom**:
- Embedding takes >100ms
- High CPU usage during embedding

**Solutions**:

1. **Batch embedding**: 52ms/query → 4ms/query (batch size 32)
2. **GPU acceleration**: 52ms → 8ms (6.5x speedup)
3. **Smaller model**: BGE-Large → BGE-Base (52ms → 28ms, but -3% accuracy)
4. **Embedding cache**: Cache hit = <1ms

**Recommended**: GPU + caching

### 12.3 Vector Search Bottleneck

**Symptom**:
- Search takes >50ms
- High memory usage

**Solutions**:

1. **Tune HNSW parameters**: ef=64 → ef=128 (better recall, +6ms)
2. **Partition data**: Search 33% of data (28ms → 12ms)
3. **Reduce result set**: limit=5 → limit=3 (28ms → 21ms)
4. **Use faster storage**: HDD → SSD (45ms → 28ms)

**Recommended**: Partitioning + SSD

### 12.4 Memory Exhaustion

**Symptom**:
- Out of memory errors
- Frequent garbage collection
- Swap usage

**Solutions**:

1. **Smaller embedding model**: 1024 dim → 768 dim (6 GB → 4.5 GB)
2. **Lower precision**: float32 → float16 (6 GB → 3 GB)
3. **Increase RAM**: 16 GB → 32 GB
4. **Offload LLM to separate server**: Separate embedding + LLM services

**Recommended**: Separate services + increase RAM

### 12.5 High Concurrent Load

**Symptom**:
- Timeouts at >100 concurrent users
- CPU at 100%

**Solutions**:

1. **Horizontal scaling**: 1 server → 4 servers (50 users → 200 users)
2. **Async processing**: Overlap I/O operations
3. **Connection pooling**: Reduce connection overhead
4. **Rate limiting**: Protect system from overload

**Recommended**: Horizontal scaling + rate limiting
