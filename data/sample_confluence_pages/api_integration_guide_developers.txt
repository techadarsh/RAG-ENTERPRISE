# API Integration Guide for Developers

## Overview

This comprehensive guide provides everything developers need to integrate with the RAG Enterprise System API. It covers authentication, endpoints, request/response formats, error handling, rate limiting, SDKs, and best practices.

**API Version**: v1.0
**Base URL**: `https://api.rag-enterprise.com/v1` (production)
**Base URL**: `http://localhost:8000` (development)
**Protocol**: REST over HTTPS
**Data Format**: JSON
**Authentication**: API Key + JWT tokens

## 1. Getting Started

### 1.1 Prerequisites

**Required**:
- API key (obtain from https://dashboard.rag-enterprise.com/api-keys)
- HTTPS client library (requests, axios, fetch)
- Basic understanding of REST APIs and JSON

**Recommended**:
- Postman or Insomnia (for testing)
- jq (for JSON parsing in terminal)
- SDK for your language (Python, JavaScript, etc.)

### 1.2 Quick Start

**Step 1: Obtain API Key**
```bash
# Log into dashboard
https://dashboard.rag-enterprise.com

# Navigate to Settings → API Keys
# Click "Generate New API Key"
# Copy key (shown only once!)
# Format: rag_pk_1234567890abcdefghijklmnop
```

**Step 2: Make Your First Request**
```bash
# Test API key
curl -X GET https://api.rag-enterprise.com/v1/health \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop"

# Expected response:
{
  "status": "healthy",
  "version": "1.0.0",
  "timestamp": "2025-10-12T10:30:00Z"
}
```

**Step 3: Submit a Query**
```bash
curl -X POST https://api.rag-enterprise.com/v1/ask \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What is our PTO policy?",
    "user_id": "user_12345"
  }'

# Expected response:
{
  "answer": "Our PTO policy offers 15-30 days per year based on tenure...",
  "sources": [
    {
      "title": "HR Policies Handbook",
      "excerpt": "PTO accrues based on years of service...",
      "score": 0.92
    }
  ],
  "conversation_id": "conv_abc123",
  "processing_time_ms": 1287
}
```

### 1.3 Environment Setup

**Development Environment**:
```bash
# Set API key as environment variable
export RAG_API_KEY="rag_pk_dev_1234567890"

# Point to local development server
export RAG_API_URL="http://localhost:8000"

# Test connection
curl $RAG_API_URL/health -H "Authorization: Bearer $RAG_API_KEY"
```

**Production Environment**:
```bash
# Production API key (never commit to Git!)
export RAG_API_KEY="rag_pk_prod_9876543210"

# Production URL
export RAG_API_URL="https://api.rag-enterprise.com/v1"
```

**Configuration File** (recommended):
```yaml

environments:
  development:
    api_url: http://localhost:8000
    api_key: ${RAG_API_KEY_DEV}
    timeout: 30
    
  production:
    api_url: https://api.rag-enterprise.com/v1
    api_key: ${RAG_API_KEY_PROD}
    timeout: 10
```

## 2. Authentication & Authorization

### 2.1 API Key Authentication

**API Key Format**:
- Prefix: `rag_pk_` (production) or `rag_pk_dev_` (development)
- Length: 32 characters (alphanumeric)
- Example: `rag_pk_1a2b3c4d5e6f7g8h9i0j1k2l3m4n5o6p`

**Including API Key in Requests**:

**Method 1: Authorization Header (Recommended)**:
```bash
curl -X GET https://api.rag-enterprise.com/v1/health \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop"
```

**Method 2: Custom Header**:
```bash
curl -X GET https://api.rag-enterprise.com/v1/health \
  -H "X-API-Key: rag_pk_1234567890abcdefghijklmnop"
```

**Method 3: Query Parameter** (not recommended for production):
```bash
curl -X GET "https://api.rag-enterprise.com/v1/health?api_key=rag_pk_1234567890abcdefghijklmnop"
```

**Security Best Practices**:
-  Store API key in environment variable or secret manager
-  Use HTTPS (never HTTP)
-  Rotate API keys every 6 months
-  Use different keys for dev/staging/production
-  Never commit API key to version control
-  Never log API key
-  Never share API key publicly

### 2.2 JWT Token Authentication (User-Specific)

**For User-Specific Operations**:
- Use API key to obtain JWT token
- JWT token represents specific user
- Include JWT in subsequent requests

**Obtain JWT Token**:
```bash
curl -X POST https://api.rag-enterprise.com/v1/auth/token \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "user_12345",
    "email": "john.doe@company.com"
  }'

# Response:
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "user_id": "user_12345"
}
```

**Use JWT Token**:
```bash
curl -X POST https://api.rag-enterprise.com/v1/ask \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What is my PTO balance?"
  }'
```

**Token Refresh**:
```bash
curl -X POST https://api.rag-enterprise.com/v1/auth/refresh \
  -H "Authorization: Bearer <current_jwt_token>"

# Response: New JWT token with extended expiration
```

### 2.3 Scopes & Permissions

**API Key Scopes**:
- `read`: Read-only access (queries, conversation history)
- `write`: Write access (document ingestion, feedback)
- `admin`: Administrative access (manage users, analytics)

**Scope Assignment**:
```bash
# When creating API key, specify scopes:
{
  "name": "Production API Key",
  "scopes": ["read", "write"],
  "rate_limit": 1000
}
```

**Check Permissions**:
```bash
curl -X GET https://api.rag-enterprise.com/v1/auth/me \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop"

# Response:
{
  "api_key_id": "key_abc123",
  "scopes": ["read", "write"],
  "rate_limit": 1000,
  "requests_today": 237
}
```

Submit a query to the RAG system.

**Authentication**: Required

**Request Body**:
```json
{

  "user_id": "user_12345",
  "conversation_id": "conv_abc123",  // Optional: for follow-up questions
  "max_sources": 5,                  // Optional: default 5
  "temperature": 0.3                 // Optional: default 0.3 (0-1)

```

**Request Example**:
```bash
curl -X POST https://api.rag-enterprise.com/v1/ask \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What is our PTO policy?",
    "user_id": "user_12345"
  }'
```

**Response** (200 OK):
```json
{
  "answer": "Our PTO policy offers 15-30 days per year based on tenure. Employees with 0-2 years receive 15 days, 3-4 years receive 20 days, and 5+ years receive 25-30 days. PTO accrues bi-weekly and can be used for vacation, personal time, or sick leave.",
  "sources": [
    {
      "id": "doc_123",
      "title": "HR Policies Handbook",
      "excerpt": "PTO accrues based on years of service: 0-2 years (15 days), 3-4 years (20 days), 5+ years (25-30 days)...",
      "score": 0.92,
      "metadata": {
        "page": 12,
        "section": "Time Off Policies",
        "last_updated": "2025-01-15"
      }
    },
    {
      "id": "doc_456",
      "title": "Employee Benefits Guide",
      "excerpt": "In addition to PTO, employees receive 10 paid holidays...",
      "score": 0.87,
      "metadata": {
        "page": 8,
        "section": "Paid Time Off"
      }
    }
  ],
  "conversation_id": "conv_abc123",
  "message_id": "msg_xyz789",
  "processing_time_ms": 1287,
  "tokens_used": {
    "embedding": 24,
    "generation": 156,
    "total": 180
  }
}
```

**Response Fields**:
- `answer`: Generated response from LLM
- `sources`: Retrieved documents (ranked by relevance score)
- `conversation_id`: ID for this conversation (use for follow-ups)
- `message_id`: Unique ID for this specific message
- `processing_time_ms`: Time taken to process request
- `tokens_used`: Token usage breakdown

**Error Response** (400 Bad Request):
```json
{
  "error": {
    "code": "INVALID_QUERY",
    "message": "Query cannot be empty",
    "details": {

      "constraint": "min_length",
```

**POST /ask/streaming**

Submit query with streaming response (real-time token generation).

**Authentication**: Required

**Request** (same as `/ask`):
```bash
curl -X POST https://api.rag-enterprise.com/v1/ask/streaming \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What is our PTO policy?",
    "user_id": "user_12345"
  }'
```

**Response** (200 OK, Server-Sent Events):
```
event: message
data: {"type": "start", "conversation_id": "conv_abc123", "message_id": "msg_xyz789"}

event: message
data: {"type": "token", "token": "Our"}

event: message
data: {"type": "token", "token": " PTO"}

event: message
data: {"type": "token", "token": " policy"}

...

event: message
data: {"type": "sources", "sources": [{...}]}

event: message
data: {"type": "end", "processing_time_ms": 1287}
```

**Client-Side Handling** (JavaScript):
```javascript
const eventSource = new EventSource('https://api.rag-enterprise.com/v1/ask/streaming');

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  
  if (data.type === 'token') {
    // Append token to UI
    appendToken(data.token);
  } else if (data.type === 'sources') {
    // Display sources
    displaySources(data.sources);
  } else if (data.type === 'end') {
    // Close connection
    eventSource.close();
  }
};
```

## 4. Request & Response Formats

### 4.1 Request Headers

**Required Headers**:
```
Authorization: Bearer <api_key_or_jwt_token>
Content-Type: application/json
```

**Optional Headers**:
```
X-Request-ID: <unique_request_id>    // For tracking/debugging
X-User-Agent: <client_info>          // Client information
Accept: application/json             // Response format (default JSON)
```

**Example**:
```bash
curl -X POST https://api.rag-enterprise.com/v1/ask \
  -H "Authorization: Bearer rag_pk_1234567890abcdefghijklmnop" \
  -H "Content-Type: application/json" \
  -H "X-Request-ID: req_abc123" \
  -H "X-User-Agent: MyApp/1.0" \
  -d '{...}'
```

### 4.2 Response Headers

**Standard Headers**:
```
Content-Type: application/json
X-Request-ID: req_abc123             // Echo request ID
X-RateLimit-Limit: 1000              // Rate limit cap
X-RateLimit-Remaining: 987           // Remaining requests
X-RateLimit-Reset: 1697234567        // Unix timestamp for reset
X-Response-Time-Ms: 1287             // Server processing time
```

### 4.3 Response Envelope

**Successful Response**:
```json
{
  // Response data here (varies by endpoint)
}
```

**Error Response**:
```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error message",
    "details": {
      // Additional error details
    },
    "request_id": "req_abc123"
  }
}
```

## 5. Error Handling

### 5.1 HTTP Status Codes

```
STATUS CODE | MEANING                | DESCRIPTION
------------|------------------------|------------------------------------------
200         | OK                     | Request successful
201         | Created                | Resource created
204         | No Content             | Request successful, no response body
400         | Bad Request            | Invalid request (validation error)
401         | Unauthorized           | Invalid or missing API key
403         | Forbidden              | Insufficient permissions
404         | Not Found              | Resource not found
429         | Too Many Requests      | Rate limit exceeded
500         | Internal Server Error  | Server error
503         | Service Unavailable    | Service temporarily unavailable
```

### 5.2 Error Codes

**Authentication Errors**:
- `INVALID_API_KEY`: API key invalid or expired
- `MISSING_API_KEY`: API key not provided
- `INSUFFICIENT_PERMISSIONS`: API key lacks required scope

**Validation Errors**:
- `INVALID_QUERY`: Query validation failed
- `MISSING_FIELD`: Required field missing
- `INVALID_FORMAT`: Field format invalid

**Resource Errors**:
- `CONVERSATION_NOT_FOUND`: Conversation ID not found
- `DOCUMENT_NOT_FOUND`: Document ID not found
- `USER_NOT_FOUND`: User ID not found

**Rate Limiting Errors**:
- `RATE_LIMIT_EXCEEDED`: Too many requests

**Server Errors**:
- `INTERNAL_ERROR`: Unexpected server error
- `SERVICE_UNAVAILABLE`: Service temporarily down

### 5.3 Error Response Examples

**400 Bad Request** (Validation Error):
```json
{
  "error": {
    "code": "INVALID_QUERY",
    "message": "Query is too long (max 500 characters)",
    "details": {
      "field": "query",
      "constraint": "max_length",
      "max_length": 500,
      "actual_length": 612
    },
    "request_id": "req_abc123"
  }
}
```

**401 Unauthorized**:
```json
{
```

### 5.4 Error Handling Best Practices

**Retry Strategy**:
```python
import time
import requests

def api_call_with_retry(url, headers, data, max_retries=3):
    for attempt in range(max_retries):
        try:
            response = requests.post(url, headers=headers, json=data, timeout=10)
            
            # Success
            if response.status_code == 200:
                return response.json()
            
            # Client error (4xx) - don't retry
            if 400 <= response.status_code < 500:
                raise Exception(f"Client error: {response.json()}")
            
            # Server error (5xx) - retry with exponential backoff
            if response.status_code >= 500:
                wait_time = 2 ** attempt  # 1s, 2s, 4s
                print(f"Server error, retrying in {wait_time}s...")
                time.sleep(wait_time)
                continue
                
        except requests.exceptions.Timeout:
            if attempt == max_retries - 1:
                raise
            wait_time = 2 ** attempt
            time.sleep(wait_time)
    
    raise Exception("Max retries exceeded")
```

**Error Logging**:
```python

    response = api_call(...)

        "request_id": e.request_id,
        "error_code": e.code,
        "url": url,

```

```
X-RateLimit-Reset: 1697234567   // Unix timestamp when limit resets
```

### 6.2 Handling Rate Limits

**Check Rate Limit Before Request**:
```python
response = requests.post(url, headers=headers, json=data)

remaining = int(response.headers.get('X-RateLimit-Remaining', 0))
reset_time = int(response.headers.get('X-RateLimit-Reset', 0))

if remaining < 10:
    wait_seconds = reset_time - time.time()
    print(f"Rate limit nearly exceeded. Resets in {wait_seconds}s")
```

**Handle 429 Response**:
```python
if response.status_code == 429:
    # Get reset time from response headers
    reset_time = int(response.headers.get('X-RateLimit-Reset', 0))
    wait_seconds = max(0, reset_time - time.time())
    
    print(f"Rate limit exceeded. Waiting {wait_seconds}s...")
    time.sleep(wait_seconds)
    
    # Retry request
    response = requests.post(url, headers=headers, json=data)
```

```json
  }
```

**Verify Webhook Signature**:
```python
import hmac
import hashlib

def verify_webhook(payload, signature, secret):
    expected_signature = hmac.new(
        secret.encode(),
        payload.encode(),
        hashlib.sha256
    ).hexdigest()
    
    return hmac.compare_digest(signature, expected_signature)

# Usage
payload = request.body
signature = request.headers.get('X-Webhook-Signature')
secret = 'your_webhook_secret'

if verify_webhook(payload, signature, secret):
    # Process webhook
    pass
else:
    # Invalid signature
    return 401
```

## 11. Code Examples

### 11.1 Python Example (Complete)

```python
import os
import requests
from typing import Dict, List, Optional

class RAGClient:
    def __init__(self, api_key: str, base_url: str = "https://api.rag-enterprise.com/v1"):
        self.api_key = api_key
        self.base_url = base_url
        self.session = requests.Session()
        self.session.headers.update({
            "Authorization": f"Bearer {api_key}",
            "Content-Type": "application/json"
        })
    
    def ask(
        self,
        query: str,
        user_id: str,
        conversation_id: Optional[str] = None,
        max_sources: int = 5
    ) -> Dict:
        """Submit query to RAG system."""
        url = f"{self.base_url}/ask"
        payload = {
            "query": query,
            "user_id": user_id,
            "max_sources": max_sources
        }
        if conversation_id:
            payload["conversation_id"] = conversation_id
        
        response = self.session.post(url, json=payload, timeout=30)
        response.raise_for_status()
        return response.json()
    
    def get_conversations(self, user_id: str, limit: int = 20) -> List[Dict]:
        """Get user's conversations."""
        url = f"{self.base_url}/conversations"
        params = {"user_id": user_id, "limit": limit}
        
        response = self.session.get(url, params=params, timeout=10)
        response.raise_for_status()
        return response.json()["conversations"]
    
    def submit_feedback(self, message_id: str, rating: int, helpful: bool, comment: str = "") -> Dict:
        """Submit feedback."""
        url = f"{self.base_url}/feedback"
        payload = {
            "message_id": message_id,
            "rating": rating,
            "helpful": helpful,
            "comment": comment
        }
        
        response = self.session.post(url, json=payload, timeout=10)
        response.raise_for_status()
        return response.json()

# Usage
if __name__ == "__main__":
    client = RAGClient(api_key=os.getenv("RAG_API_KEY"))
    
    # Submit query
    response = client.ask(
        query="What is our PTO policy?",
        user_id="user_12345"
    )
    
    print(f"Answer: {response['answer']}")
    print(f"Sources: {len(response['sources'])}")
    print(f"Processing time: {response['processing_time_ms']}ms")
    
    # Get conversations
    conversations = client.get_conversations(user_id="user_12345")
    print(f"Total conversations: {len(conversations)}")
```

## 13. Best Practices

### 13.1 Performance Optimization

**Cache Responses**:
```python
from functools import lru_cache

@lru_cache(maxsize=1000)
def get_answer(query, user_id):
    return client.ask(query=query, user_id=user_id)
```

**Batch Requests** (if possible):
```python
# Instead of:
for query in queries:
    client.ask(query=query, user_id=user_id)

# Do:
# (API doesn't support batch yet, but cache and deduplicate)
unique_queries = set(queries)
for query in unique_queries:
    get_answer(query, user_id)  # Uses cache
```

**Connection Pooling**:
```python
import requests
from requests.adapters import HTTPAdapter
from requests.packages.urllib3.util.retry import Retry

session = requests.Session()
retries = Retry(total=3, backoff_factor=1, status_forcelist=[500, 502, 503, 504])
session.mount('https://', HTTPAdapter(max_retries=retries, pool_maxsize=10))
```

### 13.2 Security Best Practices

**Store API Key Securely**:
```python
#  Good: Environment variable
api_key = os.getenv("RAG_API_KEY")

#  Better: Secret manager
from aws_secretsmanager import get_secret
api_key = get_secret("rag-api-key")

#  Bad: Hardcoded
api_key = "rag_pk_1234567890abcdefghijklmnop"
```

**Rotate API Keys**:

### 13.3 Error Handling

**Graceful Degradation**:
```python
try:
```

## 14. Migration Guide

### 14.1 Migrating from v0 to v1

**Breaking Changes**:
1. API base URL changed: `/api/` → `/v1/`
2. Authentication header: `X-API-Key` → `Authorization: Bearer`
3. Response format: `response` field renamed to `answer`

**Migration Steps**:
```python
# OLD (v0):
response = requests.post(
    'https://api.rag-enterprise.com/api/query',
    headers={'X-API-Key': api_key},
    json={'question': query}
)
answer = response.json()['response']

# NEW (v1):
response = requests.post(
    'https://api.rag-enterprise.com/v1/ask',
    headers={'Authorization': f'Bearer {api_key}'},
    json={'query': query, 'user_id': user_id}
)
answer = response.json()['answer']
```

**Backward Compatibility**:
v0 API will be supported until December 31, 2025. Migrate before then.
