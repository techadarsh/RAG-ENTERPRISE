## 1. Testing Philosophy & Principles

### 1.1 Core Principles

**Test-Driven Development (TDD)**:
- Write tests before implementation
- Red → Green → Refactor cycle
- Tests serve as specification

**Shift-Left Testing**:
- Test early in development cycle
- Catch bugs before they reach production
- Cheaper to fix bugs early (1x cost in dev vs 100x in production)

**Test Automation**:
- Automate everything possible
- Manual testing only for exploratory testing
- Fast feedback loops

**Continuous Testing**:
- Run tests on every commit
- Automated in CI/CD pipeline
- Block deployments on test failures

### 1.2 Testing Levels

```
Level          | Purpose                    | Coverage | Speed    | Frequency
---------------|----------------------------|----------|----------|-------------
Unit           | Test individual functions  | 60%      | Fast     | Every commit
Integration    | Test component interactions| 30%      | Medium   | Every commit
E2E            | Test complete user flows   | 10%      | Slow     | Before deploy
Performance    | Test speed & scalability   | N/A      | Slow     | Daily/weekly
Security       | Test vulnerabilities       | N/A      | Medium   | Weekly/monthly
```

### 1.3 Test Quality Attributes

**FIRST Principles**:
- **F**ast: Tests run quickly (<10 minutes total)
- **I**ndependent: Tests don't depend on each other
- **R**epeatable: Same result every time
- **S**elf-validating: Pass/fail without manual inspection
- **T**imely: Written at right time (before or with code)

## 2. Test Pyramid Strategy

### 2.1 Test Distribution

```
        /\
       /  \  E2E Tests (10%)
      /    \  - Full user journeys
     /------\  - UI + API + DB
    /        \ Integration Tests (30%)
   /          \ - Component interactions
  /            \ - API + DB, Service + Service
 /--------------\
/                \ Unit Tests (60%)
                  - Individual functions
                  - Pure logic testing
```

**Rationale**:
- More unit tests: Fast, cheap, precise
- Fewer E2E tests: Slow, expensive, brittle

### 2.2 Coverage Targets

**Unit Tests** (60% of total tests):
- Target coverage: 80-90%
- Critical paths: 100%
- Test: Pure functions, business logic, utilities

**Integration Tests** (30% of total tests):
- Target coverage: Key integration points
- Test: RAG pipeline, database interactions, API endpoints

**E2E Tests** (10% of total tests):
- Target coverage: Critical user journeys
- Test: Complete workflows (query → retrieve → generate → respond)

```bash
pytest tests/unit/ -n 4
```

### 3.2 Unit Test Structure

**AAA Pattern** (Arrange, Act, Assert):
```python
def test_embed_text():
    # ARRANGE: Set up test data and dependencies
    embedding_service = EmbeddingService(model_name="BAAI/bge-large-en-v1.5")
    text = "What is our PTO policy?"
    
    # ACT: Execute the function under test
    embedding = embedding_service.embed_text(text)
    
    # ASSERT: Verify the results
    assert embedding is not None
    assert len(embedding) == 1024  # BGE-Large has 1024 dimensions
    assert all(isinstance(x, float) for x in embedding)
    assert -1.0 <= max(embedding) <= 1.0  # Normalized embeddings
```

```python
    embedding_service = EmbeddingService()
    
    docs = [
        ("PTO policy text", {"category": "policies"}),
        ("Docker deployment guide", {"category": "technical"}),
        ("Benefits information", {"category": "policies"}),
    ]
    
    for text, metadata in docs:
        embedding = embedding_service.embed_text(text)
        milvus_client.insert(embedding=embedding, text=text, metadata=metadata)

        top_k=5,
        filter_expr='category == "policies"'
    )
    
    # Verify only policies returned
    assert all(r['metadata']['category'] == 'policies' for r in results)

def test_concurrent_operations(milvus_client):
    import concurrent.futures
    embedding_service = EmbeddingService()
    
    def insert_doc(doc_id):
        embedding = embedding_service.embed_text(f"Document {doc_id}")
        milvus_client.insert(
            embedding=embedding,
            text=f"Document {doc_id}",
            metadata={"id": doc_id}
        )
    
    # Insert 100 documents concurrently
    with concurrent.futures.ThreadPoolExecutor(max_workers=10) as executor:
        futures = [executor.submit(insert_doc, i) for i in range(100)]
        concurrent.futures.wait(futures)
    
    # Verify all inserted
    stats = milvus_client.get_stats()
    assert stats['row_count'] >= 100
```

```python
# tests/performance/test_performance.py
import pytest
import requests
import statistics
import time

def test_query_latency():
    """Test: Query latency is acceptable."""
    latencies = []
    
    for i in range(100):
        start = time.perf_counter()
        response = requests.post(
            "http://localhost:8000/ask",
            json={"query": "What is our PTO policy?", "user_id": "test_user"},
            headers={"Authorization": "Bearer test_api_key"}
        )
        latency = (time.perf_counter() - start) * 1000
        latencies.append(latency)
        
        assert response.status_code == 200
    
    # Assert performance targets
    p50 = statistics.median(latencies)
    p95 = statistics.quantiles(latencies, n=20)[18]
    p99 = statistics.quantiles(latencies, n=100)[98]
    
    assert p50 < 1500, f"P50 latency {p50:.2f}ms exceeds 1500ms"
    assert p95 < 2500, f"P95 latency {p95:.2f}ms exceeds 2500ms"
    assert p99 < 4000, f"P99 latency {p99:.2f}ms exceeds 4000ms"

def test_throughput():
    """Test: System handles target throughput."""
    import concurrent.futures
    
    def make_request():
        response = requests.post(
            "http://localhost:8000/ask",
            json={"query": "Test", "user_id": "test_user"},
            headers={"Authorization": "Bearer test_api_key"},
            timeout=10
        )
        return response.status_code == 200
    
    # Send 500 requests concurrently
    start = time.perf_counter()
    with concurrent.futures.ThreadPoolExecutor(max_workers=50) as executor:
        futures = [executor.submit(make_request) for _ in range(500)]
        results = [f.result() for f in futures]
    duration = time.perf_counter() - start
    
    # Calculate throughput
    throughput = 500 / duration
    success_rate = sum(results) / len(results)
    
    assert throughput >= 50, f"Throughput {throughput:.2f} req/sec is below 50"
    assert success_rate >= 0.99, f"Success rate {success_rate:.2%} is below 99%"
```

## 15. QA Best Practices

### 15.1 Testing Best Practices

**DO**:
-  Write tests before code (TDD)
-  Test one thing per test
-  Use descriptive test names
-  Arrange-Act-Assert pattern
-  Mock external dependencies
-  Clean up after tests
-  Run tests frequently
-  Maintain high coverage

**DON'T**:
-  Skip writing tests
-  Test implementation details
-  Share state between tests
-  Use sleep/wait in tests
-  Ignore flaky tests
-  Commit commented-out tests
-  Test framework code

### 15.2 Test Naming Conventions

**Good test names**:

```python
def test_embed_text_returns_correct_dimensions()
def test_search_returns_top_k_results()
def test_generate_answer_handles_timeout()
def test_query_with_empty_string_raises_value_error()
```

**Bad test names**:
```python
def test_1()
def test_embed()
def test_search_works()
def test_error()
```
